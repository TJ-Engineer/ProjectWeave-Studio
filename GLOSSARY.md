# ProjectWeave Delivery

ProjectWeave delivery language keeps product planning, execution tracking, and
release evidence distinct across the Vibe JIRA and Vibe Knowledge contexts.

## Language

**Canonical story ID**:
The stable identifier assigned by an application's plan and storyboard, such as
`KNW-01`. It remains stable even when the work is mirrored into another system.
_Avoid_: Jira ID, ticket number

**Tracker key**:
The identifier generated by Vibe JIRA for one execution issue, such as `KNW-2`.
A tracker key points to a work item; it does not replace the canonical story ID.
_Avoid_: Story ID

**Design frontier**:
The complete set of unresolved decisions whose prerequisites are already
settled and which can therefore be asked in the current grilling round.
_Avoid_: Question backlog

**Story contract**:
The confirmed outcome, acceptance criteria, permissions, affected states,
non-goals, and evidence requirements that constrain implementation.
_Avoid_: Prompt, ticket description

**Evidence gate**:
A required, observable proof that must pass before a story or release claim can
advance, such as a clean Compose startup or a browser acceptance journey.
_Avoid_: Checklist item

**Pilot issue**:
A Vibe JIRA work item used to exercise and refine the delivery workflow before
that workflow is applied broadly.
_Avoid_: Test ticket
